# `say-hi` on Homebrew

The Homebrew tap for [say-hi](https://github.com/ivylikethevine/say-hi). This
repo only packages it: the docs live on
[the say-hi site](https://ivylikethevine.github.io/say-hi/), and the tap itself
is described in
[say-hi's packaging docs](https://github.com/ivylikethevine/say-hi/blob/main/docs/PACKAGING.md#homebrew-tap).

## Install

```sh
brew install ivylikethevine/tap/say-hi
```

or tap first, then install by name:

```sh
brew tap ivylikethevine/tap
brew install say-hi
```

Homebrew puts `hi` on your `PATH`; wire it into your own shells once with:

```sh
hi --install
```

## Upgrade

```sh
brew upgrade say-hi
```

`hi --update` does not move a Homebrew install; it tells you to run
`brew upgrade` instead.

## Uninstall

```sh
hi --uninstall
brew uninstall say-hi
```

`hi --uninstall` strips hi's lines from your rc files; your own files in
`~/.config/say-hi` stay until you remove them.

## How this tap is updated

`Formula/say-hi.rb` is generated by say-hi's release workflow from
`packaging/homebrew/say-hi.rb`, which opens a pull request here for each
release. This repo's CI runs `brew style`, `brew audit --strict --online`, and
an install and `brew test` on macOS and Linux before it is merged. Change the
formula in say-hi, not here.

## Keeping this tap current

A weekly workflow (`.github/workflows/drift.yml`) compares the formula's version
with [say-hi's latest release](https://github.com/ivylikethevine/say-hi/releases/latest).
When they differ, the fix is merging the pending `say-hi-vX.Y.Z` pull request,
or re-running the `tap` job of say-hi's release workflow if none was opened. The
workflow tracks drift in one `formula-drift` issue while issues are enabled
here, and fails its run otherwise.
